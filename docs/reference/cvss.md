# CVSS の評価項目一覧

CVSS（Common Vulnerability Scoring System）は、脆弱性の深刻度を **0.0〜10.0** で表すための採点ルールです。FIRST という団体が管理しています。

- **v4.0**（2023 年 11 月公開）が最新です。
- **v3.1** もまだ広く使われています。NVD や多くのアドバイザリは v3.1 の値を載せているので、**両方読めるようにしておく**のがおすすめです。

[← 一覧に戻る](README.md)

---

## 深刻度のランク（v3.1 / v4.0 共通）

| スコア | 深刻度 |
| :---: | --- |
| 0.0 | None（なし） |
| 0.1〜3.9 | Low（低） |
| 4.0〜6.9 | Medium（中） |
| 7.0〜8.9 | High（高） |
| 9.0〜10.0 | Critical（緊急） |

## CVSS v3.1

### 基本評価基準（Base Metrics）— 脆弱性そのものの性質

| 項目 | 略号 | 選択肢 | 何を見るか |
| --- | --- | --- | --- |
| 攻撃元区分 | AV | **N** ネットワーク / **A** 隣接ネットワーク / **L** ローカル / **P** 物理 | どこから攻撃できるか。N が一番危険 |
| 攻撃条件の複雑さ | AC | **L** 低 / **H** 高 | 攻撃者が制御できない条件（競合状態など）が必要か |
| 必要な特権レベル | PR | **N** 不要 / **L** 低 / **H** 高 | ログインや管理者権限が要るか |
| ユーザー関与 | UI | **N** 不要 / **R** 要 | 被害者がリンクを踏むなどの操作が要るか |
| スコープ | S | **U** 変更なし / **C** 変更あり | 影響が脆弱なコンポーネントの外（OS や他システム）に及ぶか |
| 機密性への影響 | C | **H** 高 / **L** 低 / **N** なし | 情報が漏れるか |
| 完全性への影響 | I | **H** 高 / **L** 低 / **N** なし | データを改ざんされるか |
| 可用性への影響 | A | **H** 高 / **L** 低 / **N** なし | サービスを止められるか |

### 現状評価基準（Temporal Metrics）— 時間とともに変わる

| 項目 | 略号 | 選択肢 |
| --- | --- | --- |
| 攻撃される可能性 | E | X 未評価 / H 高 / F 機能的 / P 実証可能 / U 未実証 |
| 利用可能な対策のレベル | RL | X / U 利用不可 / W 回避策 / T 暫定 / O 正式 |
| 脆弱性情報の信頼性 | RC | X / C 確認済 / R 未確証 / U 未確認 |

### 環境評価基準（Environmental Metrics）— 自分の組織での重要度

| 項目 | 略号 | 内容 |
| --- | --- | --- |
| 機密性・完全性・可用性の要求度 | CR / IR / AR | 自社にとってその資産の C/I/A がどれだけ重要か（H/M/L） |
| 修正済み基本評価 | MAV, MAC, MPR, MUI, MS, MC, MI, MA | 自社環境に合わせて基本評価の各値を上書きする |

### ベクタ文字列の読み方

```
CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H   → 10.0 Critical（Log4Shell）
```

「ネットワーク越しに（AV:N）、簡単に（AC:L）、ログインなしで（PR:N）、誰の操作もなく（UI:N）、影響範囲が外に広がり（S:C）、情報漏えい・改ざん・停止のすべてが最大（C:H/I:H/A:H）」と読みます。

## CVSS v4.0

v3.1 からの主な変更点：

- **Temporal → Threat** に名前が変わり、項目は「攻撃コードの成熟度」だけになった
- **攻撃の前提条件（AT）** が追加され、AC から分離された
- **スコープ（S）が廃止**され、影響を「脆弱なシステム（V）」と「後続システム（S）」に分けて評価する
- ユーザー関与（UI）が 3 段階になった
- 点数に影響しない **補足評価基準（Supplemental）** が追加された
- どの評価基準を使ったかを **CVSS-B / CVSS-BT / CVSS-BE / CVSS-BTE** と明記する

### 基本評価基準（Base Metrics）

| 項目 | 略号 | 選択肢 | メモ |
| --- | --- | --- | --- |
| 攻撃元区分 | AV | N / A / L / P | v3.1 と同じ |
| 攻撃条件の複雑さ | AC | L / H | 防御機構（ASLR など）を回避する必要があるか |
| 攻撃の前提条件 | AT | **N** なし / **P** あり | **新規**。特定の設定や競合状態など、対象側の条件が要るか |
| 必要な特権レベル | PR | N / L / H | v3.1 と同じ |
| ユーザー関与 | UI | **N** 不要 / **P** 受動的 / **A** 能動的 | P はページを見るだけ、A はクリックや入力などの意図的な操作 |
| 脆弱なシステムの機密性・完全性・可用性 | VC / VI / VA | H / L / N | 脆弱な製品そのものへの影響 |
| 後続システムの機密性・完全性・可用性 | SC / SI / SA | H / L / N | 波及先（他システム）への影響。v3.1 の S:C に相当 |

### 脅威評価基準（Threat Metrics）

| 項目 | 略号 | 選択肢 |
| --- | --- | --- |
| 攻撃コードの成熟度 | E | X 未評価 / **A** 攻撃あり（悪用確認） / **P** PoC あり / **U** 報告なし |

### 環境評価基準（Environmental Metrics）

| 項目 | 略号 | 内容 |
| --- | --- | --- |
| セキュリティ要求度 | CR / IR / AR | 自社にとっての C/I/A の重要度（H/M/L） |
| 修正済み基本評価 | MAV, MAC, MAT, MPR, MUI, MVC, MVI, MVA, MSC, MSI, MSA | 自社環境に合わせて上書きする。MSI / MSA には人命に関わる **S（Safety）** も選べる |

### 補足評価基準（Supplemental Metrics）— 点数には影響しない

| 項目 | 略号 | 選択肢 | 内容 |
| --- | --- | --- | --- |
| 安全性 | S | X / N 無視できる / P 存在する | 人の安全（ケガなど）に影響するか |
| 自動化可能性 | AU | X / N いいえ / Y はい | 攻撃をワーム化して自動で広げられるか |
| 回復性 | R | X / A 自動 / U ユーザー / I 回復不能 | 攻撃後に自力で復旧できるか |
| 価値密度 | V | X / D 拡散 / C 集中 | 1 回の攻撃で得られる資源の量 |
| 対応の手間 | RE | X / L 低 / M 中 / H 高 | 対策を適用する手間 |
| 提供元の緊急度 | U | X / Clear / Green / Amber / Red | ベンダーが示す対応の緊急度 |

### ベクタ文字列の例

```
CVSS:4.0/AV:N/AC:L/AT:N/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N   → 9.3 Critical
```

## 確認問題

1. ログインフォームに SQL インジェクションがあり、未認証でネットワーク越しに DB の全データを読み書きできる。v3.1 の AV / PR / UI はそれぞれ何か。
2. 被害者が細工されたリンクをクリックしたときだけ発動する反射型 XSS。v3.1 の UI と、v4.0 の UI はそれぞれ何か。
3. CVSS 9.8 の脆弱性が見つかったが、その機能は社内ネットワークからしか使えない。どの評価基準で調整するか。

<details>
<summary>答え</summary>

1. AV:N / PR:N / UI:N（ログイン前に攻撃できるので PR:N）
2. v3.1 は UI:R、v4.0 は UI:A（クリックという能動的な操作が必要）
3. 環境評価基準（MAV を A や L に変更するなど）。基本評価の点数自体は変えない。

</details>
